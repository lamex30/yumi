# Handoff: локальный классификатор интентов («локальный Jev»)

> Документ передачи работы. Обновляется по ходу дела — любой агент, взяв ветку
> `intents-model`, может продолжить с раздела «Статус».

## Задача

Дать Yumi понимание переформулировок голосовых команд, которых нет в
`phrases`/`keywords` (actions.json), через маленькую локальную модель
классификации (по образцу «System One»-моделей типа Jev): типизированный выход +
вероятность, без генерации. Модель НЕ заменяет правила `nlu.py` — она третий
уровень после них и перед чатом.

Решение по итогам обсуждения (см. историю сессии): Jev закрыт и локально не
запускается; делаем свой аналог — **rubert-tiny2 (29M, русский) → ONNX →
onnxruntime** в основном процессе приложения.

## Архитектура (принято, не менять без причины)

```
фраза → 1) правила nlu.py (score 1.0/0.8)  → уверенно: выполнить (как сейчас)
        2) правила fuzzy 0.6 + NEGATERS + слоты {query} — не трогаем
        3) НОВОЕ: intents.classify() — ONNX-модель:
           p >= 0.85 и p(chosen) > p(chat) → выполнить команду
           иначе → чат (как сейчас)
```

- Порог 0.85 — стартовый; страховка: классификатор вызывается только после
  провала правил, `NEGATERS` отсекают «не …» до него, и гвардии: (а) класс
  `chat` в корпусе обучен негативами «команды не-кнопки» (свет, шторы, кофе,
  окно, игра) — незнакомые команды уходят в chat с вероятностью ~0.98 и потому
  не выполняются; (б) **косинус к центроидам (COS_MIN=0.75)** — нижний
  страховочный порог против далёких победителей (0.90 резал живые опечатки
  STT, «вруби песню» cos 0.77). Центроиды пишет trainer (`centroids.json`),
  ONNX экспортируется с двумя выходами (logits + embedding).
- Слоты `{query}` (поиск) классификатор не решает — url-записи с `{query}`
  им не предлагаются (пока; см. «Идеи»).
- Модель живёт в `~/.local/share/yumi/intents/` (как TTS-модели), НЕ в репо.
- Код обязана деградировать молча: нет onnxruntime/tokenizers/модели → `None`
  → работает как раньше (паттерн `_lemmatizer()` в nlu.py).

## Что осталось СОБРАННОМУ агенту (если продолжать)

1. Пользователь не перезапускал Yumi после установки модели — проверить вживую
   (`yumi --quit && yumi`), настройки → Её мозги → Распознавание фраз.
2. Лог промахов в чат (идея «judge.log») → расширение корпуса живыми фразами.
3. Слоты `{query}`: после выбора классификатором интента Search резать запрос
   старым `_slots()` из nlu.py — тогда поиск голосом заработает и на
   переформулировках.
4. При желании: `--epochs`/`--base` флаги уже есть; больше негативов в chat
   — самый дешёвый способ улучшить поведение.

### Метрики (заполнить после обучения)

```
Попытка 1 (epochs=4, lr=2e-5, batch 16): val accuracy 0.48 — модель схлопнулась
в класс chat (дисбаланс 86 против ~40 и слишком мало шагов). Правки: epochs 12,
lr 5e-5, batch 8.
Попытка 2 (epochs=12, lr=5e-5, batch 8): val accuracy 0.96 (Notes 8/8,
Play/pause 9/9, Search 6/7, Terminal 8/9, chat 17/17), модель 29.4 МБ (int8),
пробы верны. Но «открой окно» → Terminal 0.93: softmax не ловит OOV. Правки:
косинус-гвард к центроидам (COS_MIN=0.90: хорошие фразы 0.94–0.98, мусор
0.78–0.86), в chat добавлены негативы «команды не-кнопки» (свет, шторы,
кофе, окно, игра...), ONNX экспортирует logits+embedding.
Попытка 3 (негативы в chat + epochs 12): val accuracy 0.946, misses пуст.
Негативы решили OOV: весь «мусор» (окно, свет, кофе, шторы...) → chat p0.98,
то есть в чат, а не в команду. Косинус-порог снижен 0.90 → 0.75: живые
опечатки STT дают cos 0.77–0.92 («вруби песню» 0.77), резать их нельзя.
Свежие пробы (не из корпуса): все 12 «хороших» проходят с p 0.93–0.97,
все 12 «плохих» уходят в None (chat или низкий prob/косинус).
Итоговые файлы: model.onnx 29.4 МБ (int8, 2 выхода), labels.json,
centroids.json, meta.json, tokenizer.json в ~/.local/share/yumi/intents/.
```

## Ограничения и известные риски

- `predict`-уверенность на мусорной фразе бывает высокой — поэтому ступень 3
  вызывается ПОСЛЕ правил, и чат-класс («поговорить») должен побеждать интент
  при сомнении.
- Корпус сейчас покрывает интенты из `actions.example.json` (терминал, поиск,
  заметки, пауза). Свои кнопки пользователя обучаются на его phrases/keywords +
  шаблонах — качество будет скромнее, пока корпус не расширен.
- python 3.14 для обучения не годится (у torch нет колёс) — только ≤3.13.

## Идеи на потом (не в этой ветке)

- Слоты: классификатор выбирает интент «поиск», а `{query}` режется старым
  `_slots()` из nlu.py.
- Лог промахов в чат → расширение корпуса живыми фразами (идея «judge.log»
  из обсуждения).
- Дистилляция на больший корпус / дообучение по просьбе пользователя.
