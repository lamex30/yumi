# Handoff: локальный классификатор интентов («локальный Jev»)

> Документ передачи работы. Обновляется по ходу дела — любой агент, взяв ветку
> `intents-model`, может продолжить с раздела «Статус».

## Задача

Дать Yumi понимание переформулировок голосовых команд, которых нет в
`phrases`/`keywords` (actions.json), через маленькую локальную модель
классификации (по образцу «System One»-моделей типа Jev): типизированный выход +
вероятность, без генерации. Модель НЕ заменяет правила `nlu.py` — она третий
уровень после них и перед чатом.

Решение по итогам обсуждения (см. историю сессии): Jev закрыт и локально не
запускается; делаем свой аналог — **rubert-tiny2 (29M, русский) → ONNX →
onnxruntime** в основном процессе приложения.

## Архитектура (принято, не менять без причины)

```
фраза → 1) правила nlu.py (score 1.0/0.8)  → уверенно: выполнить (как сейчас)
        2) правила fuzzy 0.6 + NEGATERS + слоты {query} — не трогаем
        3) НОВОЕ: intents.classify() — ONNX-модель:
           p >= 0.85 и p(chosen) > p(chat) → выполнить команду
           иначе → чат (как сейчас)
```

- Порог 0.85 — стартовый; страховка: классификатор вызывается только после
  провала правил, `NEGATERS` отсекают «не …» до него.
- Слоты `{query}` (поиск) классификатор не решает — url-записи с `{query}`
  им не предлагаются (пока; см. «Идеи»).
- Модель живёт в `~/.local/share/yumi/intents/` (как TTS-модели), НЕ в репо.
- Код обязана деградировать молча: нет onnxruntime/tokenizers/модели → `None`
  → работает как раньше (паттерн `_lemmatizer()` в nlu.py).

## Ограничения и известные риски

- `predict`-уверенность на мусорной фразе бывает высокой — поэтому ступень 3
  вызывается ПОСЛЕ правил, и чат-класс («поговорить») должен побеждать интент
  при сомнении.
- Корпус сейчас покрывает интенты из `actions.example.json` (терминал, поиск,
  заметки, пауза). Свои кнопки пользователя обучаются на его phrases/keywords +
  шаблонах — качество будет скромнее, пока корпус не расширен.
- python 3.14 для обучения не годится (у torch нет колёс) — только ≤3.13.

## Идеи на потом (не в этой ветке)

- Слоты: классификатор выбирает интент «поиск», а `{query}` режется старым
  `_slots()` из nlu.py.
- Лог промахов в чат → расширение корпуса живыми фразами (идея «judge.log»
  из обсуждения).
- Дистилляция на больший корпус / дообучение по просьбе пользователя.
